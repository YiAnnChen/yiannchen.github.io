固定旗標 FTEC 協定的組合式正確性證明

對象是一個固定的協定：Steane [[7,1,3]] 碼、t=1、預算 r+s≤1、每個穩定子一條旗標量測電路、現有的終止規則，以及 288 項的旗標 decoder 表。我們用 CPAchecker 把「兩次觀測相同的執行不會造成邏輯錯誤」拆成 181 個單次執行的殘餘驗證與 4 條引理，再由組合器把證據接成完整的證明。

CPAchecker 無法在瀏覽器裡執行，所以本站展示它存下來的證據；另外把同一份 scalar.c 編譯成 WebAssembly，讓你在瀏覽器裡把整個有限輸入域重新窮舉一次。

驗證什麼the claim

協定在一個 Pauli frame 模型中執行：資料位元 q0…q6，症狀輔助位元 q7，旗標位元 q8。每次執行結束後，我們記下 decoder 看得到的完整觀測 m = (n, b, h₀,…,h₇)：輪數 n、分支 b（一般或旗標），以及每輪 12 位元的症狀與旗標紀錄。

定理（本模型內）
對任意兩個合法執行 f₁, f₂，若完整觀測相同，則 σ(E₁ E₂) = 0  ⟹  E₁ E₂ ∈ S   （忽略全域相位） 其中 Eᵢ 是第 i 次執行結束時、修正前的資料 Pauli 錯誤，σ 是理想症狀，S 是穩定子群。Pauli 以 (x, z) 遮罩表示，乘法就是 XOR。

直觀地說：decoder 只看得到觀測，所以兩個觀測相同的執行一定會套用同一個修正。只要它們的錯誤差異不是一個「症狀為零卻不在 S 裡」的邏輯算子，這個共同修正就不會把其中一個執行修成邏輯錯誤。

這不是直接的雙執行模型檢查。把協定展開兩次的 pair 模型在 CPAchecker 中仍是 UNKNOWN／ERROR（v3 紀錄，沒有改判）。這裡的 TRUE 來自組合式證明：181 份單次執行證據 + 4 條引理，由 compose.js 逐筆核對後接成定理。

合法配置（t=1）

無錯誤；一個重量一的初始資料錯誤（r=1, s=0，7 位元 × 3 種 = 21）；或乾淨基線前三輪內的一個電路故障（r=0, s=1，3 輪 × 6 穩定子 × 94 = 1,692）。

不在模型內

idle 故障、古典控制故障、修正操作本身的故障，以及 t>1、r+s>1、其他碼或其他 decoder。

協定the fixed protocol

Steane 碼的 X、Z 穩定子都由 Hamming 矩陣 H = {120, 102, 85}（二進位遮罩）的三列給出。每一輪依序量測 3 個 Z 型穩定子（k=0,1,2）和 3 個 X 型穩定子（k=3,4,5）。每個量測電路有 10 個操作：

操作內容可注入的故障
op0, op1準備症狀位元 q7、旗標位元 q8準備翻轉（1 種）
op2…op76 個 CNOT：4 個連到資料位元，第 2、5 個（op3、op6）連到旗標CNOT 後任意非恆等兩位元 Pauli（15 種）
op8, op9量測 q7、q8量測翻轉（1 種）

終止規則

若某輪任一旗標為 1，再做兩輪完整量測後停止，走旗標分支；否則連續三輪症狀相同就停止，走一般分支。容量上限 8 輪由 check(n<8u) 以 assertion 保護，超出會報錯而不是被裁掉。

Decoder

一般分支：用最後一輪的 6 位元症狀做 Hamming 解碼。旗標分支：查一張由 Python 參考模型窮舉產生、共 288 項的完整歷史表。v4_1 把兩者包成只讀參數的純函式：

unsigned correction(unsigned n,unsigned b,unsigned h0,...,unsigned h7) {
 unsigned last;
 if(b) return flaglookup(n,h0,h1,h2,h3,h4,h5,h6,h7);
 last=n==1u?h0:n==2u?h1:n==3u?h2:n==4u?h3:n==5u?h4:n==6u?h5:n==7u?h6:h7;
 return decode(last&63u); }

找不到表項時回傳哨兵 0x80000000u，run() 以 check(cor!=0x80000000u) 把它當成錯誤。

本站不接受其他輸入

v1 只驗證這一個協定。碼、t、電路、終止規則與 decoder 表都固定在 scalar.c 裡，網頁不提供修改介面。

證明鏈proof chain

每一步都是一個（或一組）CPAchecker 驗證工作，全部使用 config/bmc.properties、迴圈界限 128、位元向量編碼。

  1. 每個合法執行都滿足殘餘界限

    把 1,714 種輸入分成 181 個互斥區（initial 區 22 種，加上每個「輪 R、穩定子 K、操作 O」一區）。每區驗證真正的 run()，證明 wt_min(C·E) ≤ s、r+s ≤ 1，並且 ec == correction(觀測)。組合器獨立重算輸入域，確認覆蓋完整且互斥。
    residual/*.c · manifest.json · results/residual/*

  2. 預算放寬

    由 rᵢ+sᵢ ≤ 1 得 sᵢ ≤ 1，所以 wt_min(C·Eᵢ) ≤ 1。
    budget_relaxation.c · TRUE

  3. 單一殘餘的症狀與奇偶關係

    若 wt_min(A) ≤ 1，則 parity(aₓ) = [σₓ(A) ≠ 0]，Z 部分同理。
    residual_signature.c · TRUE

  4. 同觀測 → 同修正（機器檢查）

    181 區每一區都證明 ec == correction(en,eb,eh0..eh7)；common_correction.c 再證明在中間把所有全域輸出改成任意值後，correction() 的結果不變。所以 M(f₁)=M(f₂) 蘊含 C₁=C₂。
    common_correction.c · TRUE；對照 common_correction_broken.c · FALSE

  5. 消去共同修正，推出 pair 條件

    令 Aᵢ = C·Eᵢ，則 A₁ ⊕ A₂ = E₁ ⊕ E₂ = D。若 σ(D)=0，則兩個殘餘的症狀相同，由步驟 3 它們的奇偶也相同，所以 D 的 X、Z 奇偶皆為偶，即 D ∈ S。
    signature_pair.c · TRUE；對照 pair_bridge_broken.c · FALSE

步驟 3、5 的奇偶引理只對 Steane（CSS 碼）與 t=1 成立。一般碼距論證 wt(P₁P₂) ≤ s₁+s₂ < d 沒有經過機器檢查。完整推導見 PROOF_REVIEW_zh.md。

對照組的作用

每條關鍵引理都配一個刻意弄壞的版本，預期 FALSE。它們確認檢查真的能抓到錯誤，不是因為前提恆假而「空洞地」成立。

殘餘界限失敗時

若某個 decoder 讓步驟 1 失敗，結論是組合式證明不適用，不是「協定錯誤」。pair 條件可能仍然成立，兩者必須分開回報。Playground 的對照 A 示範這種情況。

TRUE 在這裡的意思

BMC 搭配 bounding assertions：若迴圈界限 128 不足以涵蓋所有路徑，結果會是 UNKNOWN，不會是 TRUE。

位元精確

bitprecise_wrap（TRUE）與 _bad（FALSE）確認 unsigned 溢位是以 32 位元位元向量精確建模。

為什麼不在瀏覽器跑 CPAchecker

CPAchecker 是 Java 程式並依賴原生 SMT 求解器。瀏覽器端改由 WASM 窮舉同一個有限模型，作為獨立的交叉檢查。

位元編碼

量編碼
Pauli E兩個 7 位元遮罩 (x, z)；第 q 位為 1 表示 q 上有 X（或 Z）成分，兩者皆 1 為 Y。乘法 = XOR，忽略相位。
症狀 sy(x,z)6 位元：低 3 位是 x 對 H 各列的奇偶（Z 型穩定子量到），高 3 位是 z 的奇偶。
每輪紀錄 h_i12 位元 word = v | (flags<<6)：位元 0–5 是 6 個穩定子的量測結果，位元 6–11 是對應旗標。
修正 ec14 位元：低 7 位 X、高 7 位 Z。0x80000000 是找不到表項的哨兵值。
故障輸入run(mode,q,a,fr,fk,fo,fp)：mode 0 無錯誤、1 初始錯誤（q 位，a=1 X／2 Z／3 Y）、2 電路故障（輪 fr、穩定子 fk、操作 fo、Pauli fp）。CNOT 故障的 fp 低 2 位作用在 control、高 2 位作用在 target。

原始檔

scalar.c被驗證的模型（v4_1） residual/r1_k0_op2.c一份殘餘分區入口範例 residual/initial.cinitial 區（22 種輸入） legacy.cv2 獨立實作，Playground 用來比對 ftec_wasm.cWASM 驗證程式（Playground） PROOF_REVIEW_zh.md嚴格重述、推導與程式對照

WASM 與證據用的是同一份模型

Playground 會先下載 scalar.c，在瀏覽器裡計算 SHA-256，與每筆 CPAchecker 紀錄的 modelSHA256 比對，再執行由這份檔案編譯出的 WASM。

範圍與限制scope

  1. t=1 寫死在模型、residual()（只列舉重量一）與輸入域（1,714 種）裡。residual() 開頭的 check(s<=1u) 會擋下越界呼叫。
  2. 旗標 decoder 是 Python 窮舉產生的 288 項表；驗證過程不列舉控制流，但建模流程本身用了列舉。
  3. 步驟 3、5 的奇偶引理只對 Steane、t=1 成立；一般碼距論證沒有機器檢查。
  4. 物理模型（閘的錯誤傳遞、量測基底、旗標電路）只做過三份同源實作（Python、legacy C、scalar C）的差異測試，還沒有用 Stim 之類獨立的穩定子模擬器核對。
  5. 直接雙執行的 pair 分析沒有完成，v3 紀錄維持 UNKNOWN／ERROR。
  6. 若 decoder 讓殘餘界限不成立，組合式證明就不適用；這不代表 pair 條件不成立。

重現reproduce

需要 Java 21、CPAchecker 4.2.2 與 Node。在 ftec_compositional_v4_1 資料夾中：

node partitions.js                       # 產生 181 份殘餘入口與 manifest，並檢查覆蓋
node run_partitions.js --resume --seconds 60
node run_lemmas.js                       # 引理與對照組
node compose.js                          # 核對全部證據，寫出 COMPOSITION.json
node test_compose.js                     # 確認組合器會拒絕失效證據

本站的 WASM 由 YoWASP 的 Clang（編譯成 WebAssembly 的 LLVM）建置，不需要原生編譯器：

npm i @yowasp/clang
node tools/build_wasm.mjs      # ftec/src/*.c → ftec/assets/ftec.wasm
node tools/test_wasm.mjs       # 在 Node 中跑一次 Playground 的全部檢查
